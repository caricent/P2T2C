# Migration — P2T2C 0.3.0 to 0.4.0

## Summary

This migration makes the managed P2T2C template English-first and single-file bilingual for global developer adoption.

## Workflow Changes

- Core workflow semantics are unchanged:
  - Proposal -> Change Pack -> Gate A -> Truth Patch + Execution Pack -> Coding -> Acceptance -> Closure Report
  - Gate A approves Change Pack application.
  - Gate B resolves Truth Drift only.
  - Change Pack Admission Summary still controls Fast Path vs Blocked Path.
- Language metadata changes from `zh-CN` / `Workflow CN` to English-first bilingual:
  - `language: en-US`
  - `supported_languages: [en-US, zh-CN]`
  - `language_policy: english_first_single_file_bilingual`
- Managed docs, prompts, templates, README files, and migration notes now present English first with Chinese equivalents in the same file.
- Shell script runtime output remains English-only.

  - Proposal -> Change Pack -> Gate A -> Truth Patch + Execution Pack -> Coding -> Acceptance -> Closure Report
  - `language: en-US`
  - `supported_languages: [en-US, zh-CN]`
  - `language_policy: english_first_single_file_bilingual`

## Upgrade Package Changes

- Updates `P2T2C_TEMPLATE_VERSION` to `0.4.0`.
- Updates `.p2t2c/manifest.yaml`, `docs/sot/manifest.yaml`, and `project_config.example.yaml` language metadata.
- Updates managed documentation and template content in place.
- Adds this migration note to the managed migration list.
- Regenerates `CHECKSUMS.sha256` and `.p2t2c/lock.sha256`.

## Compatibility

- Existing CPs, specs, tasks, and Closure Reports remain historical records.
- New CPs after upgrade should use the English-first bilingual templates.
- Project-owned business Truth, ADRs, specs, code, tests, database files, package manifests, and historical Closure Reports are not modified by the upgrade.
- CLI flags, Makefile targets, install behavior, upgrade behavior, and rollback behavior are unchanged.

## Required Validation

```bash
make check
shasum -a 256 -c CHECKSUMS.sha256
```
