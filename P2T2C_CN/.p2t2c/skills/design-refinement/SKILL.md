# 设计澄清

仅当歧义会改变实现结果时使用本方法。它澄清意图，不定义业务规则。

1. 读取 P2T2C 入口、项目配置、相关 Truth、ADR 和实现证据。
2. 写明目标、非目标、验收行为以及尚未决定的准确问题。
3. 给出可行选项、推荐项，以及对 Truth、风险和验证的影响。
4. 将人类决定记录在当前指令、可选 SP 或 R2 CPK 中。若改变当前行为，必须经过 Gate A 和 Truth Patch。
5. 仅在意图无冲突后恢复风险路由。

不得仅为使用本方法而创建独立设计产物。SP 始终可选，任何方法产物都不能成为业务规则的唯一来源。
