## Expansion and Recovery

The prepared directory contains proposal.md, design.md, tasks.md, and source.sha256 for the source SP observed during preparation; --source-digest is an alternative. Targeted validation returns source_digest. Stale candidates cannot overwrite changed sources. Preserve structured progress and recorded checks; review the semantic content mapping separately.

Retry the original command after interruption or run p2t2c recover --proposal SP-... --json. Recovery is bound to the specific work, never another SP in the shared directory. Preserve concurrent user content and report its path instead of forcing an overwrite.

.p2t2c/documents/ and .p2t2c/prepared/ are local runtime/preparation areas; suggest them for project-owned ignore rules. They are not task evidence ledgers to fill or commit. Successful transactions discard payload copies and retain small mechanical recovery/idempotency metadata.

## Downgrade

Use the current 0.16 upgrade/rollback entry point. It checks target runtime capabilities before replacement and rejects incompatible compact records, including completed records, or unfinished transactions. Do not fake a schema change or automatically convert records for downgrade.

Published older scripts cannot acquire this new preflight; manually copying old runtime files does not provide compatibility. Layout migration remains a separate docs-migrate operation and cannot interleave with document writes or unresolved transactions.
