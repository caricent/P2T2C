# 0.13.0 到 0.14.0 迁移

本版本加入自适应路由、与代码状态绑定的机器证据，以及单一确定性受管文件清单。升级只更新工作流外壳，不会重写项目拥有的 Truth、ADR、SP、CPK/CR 实例、spec、代码、测试、数据库或 `.p2t2c/project_config.yaml`。

## 新安装行为

新安装默认获得 `methodology.profile: p2t2c-adaptive-v2` 与 `enforcement: advisory`，并包含 R0 audit/residual-risk 控制、四个具名验证档位、`{id, run}` 命令和以 catch-all 结尾的有序路径映射。新 CPK 使用 `schema_version: 3`，声明 `execution_shape: spike | bounded | architectural`，并绑定 Gate A/B、Truth ref+digest、implementer、TDD policy、ownership batch 与 legacy-startup 例外。

安装后的工作流外壳包含事件 runner、收口投射工具、JSON Schema、`work.md` 模板和 adaptive-v2 行为 eval 场景。临时 ledger 位于已忽略的 `.p2t2c/runs/<work-id>/` 目录。

发行根自身包含 required 模式的项目拥有 `.p2t2c/project_config.yaml`，使发行证据必须完整。这些文件不受管也不安装；新目标收到 advisory 示例配置。

## 既有项目兼容

升级逐字节保留既有项目配置。没有 `methodology` 配置的项目继续处于 advisory。`p2t2c-balanced-v1`、schema v2 CPK 与 CR、既有 spec/plan/tasks 执行包继续有效；历史产物不会迁移，也不会按 v3 重新校验。新的 bounded 工作不得保留 spec/plan/tasks；只有显式使用 `legacy_startup_evidence: true` 的 architectural CPK 可以保留迁移前已创建的三件套。

如需安全启用，请审阅 `.p2t2c/templates/project_config.example.yaml`，把 adaptive-v2 methodology 与 verification 段合并到项目拥有的配置中，保留 `enforcement: advisory`，在保留稳定 ID 的前提下把 command `run` 替换为项目实际命令，保留最终 catch-all 路径规则，并只对新工作使用 v3 模板。每个 changed path 都必须匹配；缺少映射与 profile 降级在 advisory 中仍是硬失败。

R0 默认仍不创建产物。Audit CR 要求 `p2t2c.r0.audit_mode: true`；residual-risk CR 要求 `closure_on_residual_risk: true`、recorded 状态与非 none 风险引用。Gate A pending 时只允许只读 exploration、route 与 isolation。Truth ref/digest、schema、路由、path mapping、final tree 和目标原子恢复在 advisory/required 中都是硬门；advisory 只把不完整的方法证据记录为 warning。

## 晋级 Required

仓库内的 3×3 场景只是 eval 定义，不代表已产生真实 Agent 结果。只有完成真实的 0.13 与 adaptive-v2 Agent A/B，并记录效率目标达成且缺陷逃逸、返工和 Truth Drift 均未恶化后，才可晋级 `enforcement: required`。随后在同一 final tree 上运行由路径选择出的完整 full 与 governance 命令集，保留 eval 结果引用，只把 `methodology.enforcement` 改为 `required`，再运行普通 checker。

## 安全升级与回滚

先运行 `p2t2c_upgrade.sh --dry-run`。源发行根的 `.p2t2c/managed-files.txt` 是安装、升级、lock 与 checksum 使用的精确清单。Apply 前，所有清单资产必须被 `CHECKSUMS.sha256` 覆盖并通过校验。源发行不完整或损坏、受管文件被本地修改，或待淘汰受管文件与记录 lock 不一致时，apply 会停线。

Apply 会记录备份和所有新建文件。Post-apply checker 失败时返回非零并自动恢复旧受管资产与 lock。Rollback 只删除本次升级新建的文件，保留项目配置与实例产物，且不会删除运行时证据。
