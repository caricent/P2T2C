# 0.6.0 到 0.7.0 迁移

## 摘要

本次迁移继续收敛 P2T2C 安装后的项目根目录文件，避免与使用者项目自身的 `README.md`、`AGENTS.md`、`Makefile` 和常见元数据文件重名冲突。

P2T2C 的人类入口和 AI 入口仍保留在项目根目录，但使用 P2T2C 专属文件名：

- `P2T2C_README.md`
- `P2T2C_AGENTS.md`

其他 P2T2C 元数据移动到 `.p2t2c/` 下。

## 路径映射

| 旧路径 | 新路径 |
|---|---|
| `README.md` | `P2T2C_README.md` |
| `AGENTS.md` | `P2T2C_AGENTS.md` |
| `CHECKSUMS.sha256` | `.p2t2c/CHECKSUMS.sha256` |
| `P2T2C_TEMPLATE_VERSION` | `.p2t2c/VERSION` |
| `P2T2C_LICENSE.md` | `.p2t2c/P2T2C_LICENSE.md` |
| `project_config.example.yaml` | `.p2t2c/templates/project_config.example.yaml` |

## 升级规则

- 新安装不再创建根级 `README.md`、`AGENTS.md`、`Makefile`、`CHECKSUMS.sha256`、`P2T2C_TEMPLATE_VERSION`、`P2T2C_LICENSE.md` 或 `project_config.example.yaml`。
- 升级现有项目时，旧根文件只有在当前 hash 与 `.p2t2c/lock.sha256` 匹配时才会移除。
- 旧 `README.md`、`AGENTS.md` 或 `Makefile` 被本地修改时，升级必须停线并生成冲突报告。
- 如果某些 AI 工具只自动读取根级 `AGENTS.md`，使用者应在项目自己的 `AGENTS.md` 中手动引用 `P2T2C_AGENTS.md`。

## Obsolete managed files

当 lock hash 证明以下旧路径未被本地修改时，升级脚本可以移除它们。

```text
BEGIN_OBSOLETE_MANAGED
README.md
AGENTS.md
CHECKSUMS.sha256
P2T2C_TEMPLATE_VERSION
P2T2C_LICENSE.md
project_config.example.yaml
Makefile
END_OBSOLETE_MANAGED
```
