# 0.14.1 to 0.15.0 Migration

Version 0.15 adds an action-oriented core document workflow, while normal upgrade never migrates or rewrites project documents.

## New Work

- R0 is zero-artifact exploration.
- R1/R2 uses `docs/proposals/SP-*.md` and `docs/specs/<change>/{design.md,tasks.md}`.
- SOT is the only current behavioral authority; Decision Records live inside SOT.
- Archive runs no tests, review, or release smoke and only completes tasks.md in place.

## Legacy Compatibility

- Open CPK v3/runs continue through 0.14.1 context/status/evidence/verify/close.
- Defaults, verification profiles, event v1, and receipt v1/v2 semantics remain unchanged.
- Project config, SOT, CPK, CR, sidecar, cache, and legacy specs remain byte-for-byte intact.

## Document Layout

Normal upgrade installs only the new tools and empty active roots. After every legacy work item is closed, users may explicitly run:

```text
p2t2c docs-migrate --dry-run --decision-map FILE
p2t2c docs-migrate --apply --decision-map FILE
```

Migration processes every legacy-root file individually: SPs enter `docs/proposals/`, superseded proposal scaffolding enters `docs/reference/archive/proposals/`, and ADR, CPK, CR/evidence, and root specs originals enter their corresponding cold archives. A human must first write ADR decisions into current SOT and provide an ADR-to-DEC-anchor mapping. Document layout must be rolled back before template rollback.
