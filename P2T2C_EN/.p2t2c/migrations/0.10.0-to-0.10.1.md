# 0.10.0 to 0.10.1 Migration

This migration refines when Gate A is required after an SP produces a CPK.

## Behavioral changes

- If an SP does not require SoT or ADR changes, AI uses Fast Path and generates the CPK directly.
- If an SP requires SoT or ADR changes, the CPK must set `Gate A required: Yes` and use explicit human decision options before those changes are applied.
- Execution Pack generation may proceed without Gate A only when the CPK records `Gate A required: No` and existing SoT/ADR already define the required rules.

## Updated workflow files

| File | Change |
|---|---|
| `P2T2C_AGENTS.md`, `P2T2C_README.md` | Clarify that Gate A is required only for SoT/ADR changes. |
| `docs/submit_proposals/SP_TEMPLATE.md`, `docs/submit_proposals/README.md` | Route no-SoT/ADR SPs directly to CPK generation and SoT/ADR SPs to Gate A options. |
| `.p2t2c/templates/change_packs/CHANGE_PACK_TEMPLATE.md` | Adds `SoT / ADR change required` and `Gate A required` routing fields. |
| `.p2t2c/prompts/02_generate_change_pack_prompt.md` | Requires the CPK to classify whether SoT/ADR changes are needed. |
| `.p2t2c/prompts/03_apply_change_pack_prompt.md` | Applies only when the CPK requires SoT/ADR changes and Gate A approves. |
| `.p2t2c/prompts/04_generate_execution_pack_prompt.md` | Allows execution docs after a no-SoT/ADR CPK without Gate A. |
| `docs/sot/manifest.yaml`, `.p2t2c/templates/project_config.example.yaml` | Rename Gate A label to applying SoT/ADR changes. |

## Project-owned files

Business Truth, ADR instances, SP instances, specs, code, tests, database files, package manifests, and historical Closure Reports are not migrated or rewritten.
