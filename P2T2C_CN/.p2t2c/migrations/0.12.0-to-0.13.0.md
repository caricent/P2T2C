# 0.12.0 到 0.13.0 迁移

本发行新增 P2T2C 原生执行方法层：设计澄清、风险感知 TDD、根因调试、独立审查和工作区隔离。它只更新受管工作流资产，绝不重写项目拥有的 Truth、ADR、实例产物、spec、代码、测试或历史 CR。

## 新安装行为

新安装获得带有 `enforcement: required` 的 `methodology` 示例配置。新的 R1/R2 CPK 模板声明 `methodology_profile: p2t2c-balanced-v1`，新的执行/收口模板记录方法检查点和证据。新的 CPK 和收口模板声明 `schema_version: 2`；v2 Closure 还声明 `verification_policy: fresh_pass`。

## 既有项目兼容性

既有 `.p2t2c/project_config.yaml` 不会被修改。缺少 `methodology` 段时，治理检查使用 advisory 模式，历史制品保持有效。若要启用 required 强制执行，请从新示例复制配置块，并让后续新工作使用新的 CPK/spec/plan/tasks/CR 模板。

required 模式下启用方法层的 Closure 需要新鲜验证证据、测试先行 RED 证据或记录在案的豁免、隔离/基线证据和所需的独立审查结论。R2 始终需要独立审查。

## 安全升级

先执行 upgrade dry-run。仅当没有本地受管文件冲突时，升级才创建原生 skills 和来源说明。本次迁移没有过时的受管资产。
