# Tool Integration Guidance

Project entry points are project-owned and are not overwritten by installation. Keep project-specific permissions, build requirements, and necessary acceptance, with a short route to P2T2C_AGENTS.md rather than duplicated governance or per-model recipes.

Suggested text for explicit project adoption:

> Use P2T2C_AGENTS.md for the workflow; only docs/sot/** defines current behavior. Read applicable original clauses, exceptions, and dependencies. The model chooses retrieval, implementation, diagnosis, and checks and continues within clear authorization. Necessary project checks remain binding. Stop a change with unresolved new semantics; unmet necessary acceptance cannot complete. Preserve standard/legacy identity; the model prefers compact for eligible simple R1 when consumer wrappers support it. Match checks to impact, reuse applicable results, and archive once without stacking diagnostic commands.

Codex, Claude Code, and Cursor entry points should reference the same authority instead of maintaining separate policies. Locate full-file reading, repeated confirmation, legacy-routing, and wrapper conflicts and change them through an explicit project change. Fresh-session validation observes a real task path rather than a recital of rules.
