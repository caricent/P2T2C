# 0.10.1 到 0.11.0 迁移

本次迁移补强 single_task 阶段的 acceptance 合并、自报告和失败 triage 纪律。它不引入业务规则，也不修改项目 Truth。

## 行为变化

- `.p2t2c/prompts/05_execute_single_task_prompt.md` 新增 R1/R2/R3：
  - R1 允许同 spec、同领域对象、同源 suite 的连续 task 在链路终点合并执行完整 Acceptance。
  - R2 对环境性失败采用项目可扩展白名单，命中后最多重试 1 次。
  - R3 要求失败后先 triage，并固定分类为 `compile_error`、`unit_assertion`、`sandbox_environment`、`runtime_crash`。
- `docs/sot/governance/P2T2C_GOVERNANCE.md` 新增 `RULE-GOV-013`，只固化自报告契约：task 必须声明 `Acceptance scope:`；失败后必须在 Actual 记录 triage 标签和重试次数。
- `.p2t2c/templates/execution/tasks.md` 增加 `Acceptance scope: single` 默认字段、失败 Actual 示例和最终验收检查项。
- `phase_rules.txt` 仍由 `check_p2t2c.sh` 生成；`single_task` 与 `acceptance` 会自动包含 `RULE-GOV-013`。

## 项目侧推荐实现

下游项目可以定义 feature-level closure command，例如 `make closure`，其语义是项目定义的非 UI、非 perf 验收闭集。P2T2C 不强制该命名；没有该命令的项目可以继续使用自己的 feature-level build/test/check 命令。

下游项目也可以定义 warm test 变体，例如 `<test-target>-warm`，用于在一次成功 build 后跳过重复 build。该能力属于项目构建脚本，不属于上游 P2T2C 工作流外壳。

项目栈的 R2 环境关键字和 R3 triage 工具路径应写在项目自有 `AGENTS.md` 或等价 AI 入口，不应写入受管的 `P2T2C_AGENTS.md`。
