# 0.13.0 to 0.14.0 Migration

This release adds adaptive routing, machine-bound execution evidence, and a single deterministic managed-file inventory. Upgrade changes only the workflow shell. It does not rewrite project-owned Truth, ADRs, SPs, CPK or CR instances, specs, code, tests, databases, or `.p2t2c/project_config.yaml`.

## New Install Behavior

New installations receive `methodology.profile: p2t2c-adaptive-v2` with `enforcement: advisory`, R0 audit/residual-risk controls, four named verification profiles, `{id, run}` commands, and an ordered path map ending in a catch-all. New CPKs use `schema_version: 3`, declare `execution_shape: spike | bounded | architectural`, and bind Gate A/B, Truth ref+digest, implementer, TDD policy, ownership batches, and any legacy-startup exception.

The installed shell includes the event runner, closure projector, JSON schemas, `work.md` template, and the adaptive-v2 behavior-eval scenarios. Runtime ledgers live under the ignored `.p2t2c/runs/<work-id>/` tree.

The release roots themselves contain project-owned `.p2t2c/project_config.yaml` files in required mode so release evidence must be complete. Those files are not managed or installed; a new target receives the advisory example instead.

## Existing Project Compatibility

Upgrade preserves the existing project configuration byte-for-byte. A project with no `methodology` configuration remains advisory. `p2t2c-balanced-v1`, schema v2 CPKs and CRs, and existing spec/plan/tasks packs remain valid; historical artifacts are not migrated or revalidated as v3. New bounded work cannot retain spec/plan/tasks. Only an architectural CPK explicitly marked `legacy_startup_evidence: true` may retain the trio created before migration.

To opt in safely, review `.p2t2c/templates/project_config.example.yaml`, copy the adaptive-v2 methodology and verification sections into the project-owned configuration, keep `enforcement: advisory`, replace baseline command `run` values with project-specific commands while retaining stable IDs, retain a final catch-all path rule, and use v3 templates only for new work. Every changed path must match; missing mappings and profile downgrades remain hard failures in advisory mode.

R0 still creates no artifact by default. An audit CR requires `p2t2c.r0.audit_mode: true`; a residual-risk CR requires `closure_on_residual_risk: true`, recorded status, and a non-none risk reference. Gate A pending permits only read-only exploration, route, and isolation. Truth ref/digest, schema, routing, path mapping, final tree, and atomic target restoration are hard gates in both advisory and required modes; advisory only records incomplete method evidence as warnings.

## Promotion to Required

The checked-in 3×3 scenarios are evaluation definitions, not claimed Agent results. Promote a project to `enforcement: required` only after running real 0.13-versus-adaptive-v2 Agent A/B evaluation and recording that the agreed efficiency targets were met without worse defect escape, rework, or Truth Drift. Then run the complete path-selected full and governance command sets on one final tree, retain the evaluation reference, change only `methodology.enforcement` to `required`, and rerun the normal checker.

## Safe Upgrade and Rollback

Run `p2t2c_upgrade.sh --dry-run` first. The source `.p2t2c/managed-files.txt` is the exact install, upgrade, lock, and checksum inventory. Before apply, every listed source asset must be covered by and pass `CHECKSUMS.sha256`. Apply stops on an incomplete or corrupt source, a locally modified managed file, or an obsolete managed file whose recorded lock no longer matches.

Apply records backups and every created file. A post-apply checker failure returns nonzero and automatically restores the previous managed assets and lock. Rollback removes only files created by this upgrade, preserves project-owned configuration and artifacts, and never removes runtime evidence.
