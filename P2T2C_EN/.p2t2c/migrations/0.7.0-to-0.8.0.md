# 0.7.0 to 0.8.0 Migration

## Summary

This migration strengthens the Truth layer with three machine-checkable guarantees, projected from three new governance rules. No files are renamed or removed; the change is additive.

- `RULE-GOV-009` — Rule identifier integrity: SoT rule identifiers must be unique, lifecycle links must be bidirectional, references must resolve, and a superseded rule must not stay `Active`.
- `RULE-GOV-010` — Code-to-Truth back-reference anchors: code that implements a rule carries a pointer-only `Implements: RULE-...` comment; the scan is soft and runs only when a `src/` tree exists.
- `RULE-GOV-011` — EARS acceptance binds to rule identifiers: each EARS acceptance statement and each task acceptance step names the rule identifier it verifies.

## Upgrade rules

- This migration is additive. It declares no obsolete managed files.
- The new SoT integrity scan runs against `docs/sot/**` in every release root and in every installed project.
- The code-anchor scan is soft: it is skipped when no `src/` tree exists, so empty template roots and docs-only projects are unaffected.
- Existing project Truth that already uses unique identifiers and bidirectional lifecycle links passes without edits. Projects with duplicate identifiers, dangling references, or a superseded-yet-`Active` rule must resolve those before `make check` passes.
