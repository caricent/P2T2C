# 0.14.1 到 0.15.0 迁移

0.15 新增动作式核心文档流，但普通 upgrade 不迁移或改写项目文档。

## 新工作

- R0 为零文档探索。
- R1/R2 使用 `docs/proposals/SP-*.md` 与 `docs/specs/<change>/{design.md,tasks.md}`。
- SOT 是唯一当前行为权威，Decision Record 位于 SOT。
- Archive 不运行测试、review 或 release smoke，只原地完成 tasks.md。

## Legacy 兼容

- 打开的 CPK v3/run 继续使用 0.14.1 context/status/evidence/verify/close。
- defaults、verification profile、event v1 与 receipt v1/v2 语义不变。
- project_config、SOT、CPK、CR、sidecar、cache 与旧 specs 逐字节保留。

## 文档布局

普通 upgrade 只安装新工具与空活动目录，不移动旧文件。关闭所有 legacy work 后，用户可显式运行：

```text
p2t2c docs-migrate --dry-run --decision-map FILE
p2t2c docs-migrate --apply --decision-map FILE
```

迁移逐文件处理所有 legacy 根：SP 进入 `docs/proposals/`，被替代的旧 proposal 脚手架进入 `docs/reference/archive/proposals/`，其余 ADR、CPK、CR/evidence 与根 specs 原文进入对应冷归档。迁移必须先由人类把 ADR 决策写入当前 SOT 并提供 ADR 到 DEC anchor 的映射。模板 rollback 前必须先 rollback 文档布局。
