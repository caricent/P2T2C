# 0.14.0 到 0.14.1 迁移

本补丁版本在不改变 `p2t2c-adaptive-v2` 风险、Gate、审查与修复契约的前提下，降低默认上下文和重复执行。升级只替换发行受管工作流资产，不会改写项目配置、Truth、ADR、CPK/CR 实例、证据 sidecar、活动 run 状态、代码、测试或数据库。

## 新安装行为

新安装包含确定性的 `p2t2c context`、`status`、`evidence summary` 视图、三个阶段 Skill、引用内容寻址证据 sidecar 的 receipt v2、单进程 checker 与安全 closed-proof cache，以及 coverage-aware 批量验证。项目拥有配置现在是叠加在受管 `.p2t2c/defaults.yaml` 上的紧凑身份/advisory overlay。验证命令对象可声明 `read_only`、`parallel_group` 和 `covers`。默认方法 profile 仍为 advisory 模式的 `p2t2c-adaptive-v2`。

## 既有项目兼容

升级逐字节保留 `.p2t2c/project_config.yaml`，并保持完整 legacy 配置的 effective digest 与语义。未声明可选 metadata 的旧命令对象继续使用 0.14.0 默认值：非只读、无并行组、无 coverage。省略的受控 section 继承受管 defaults；显式存在但残缺的 methodology、verification 或 mapping override 会停止验证，不会静默混合两层。历史 inline receipt v1 收口继续有效且不会转换成 sidecar。既有 schema v2/v3 制品和打开的 `.p2t2c/runs/**` ledger 保持有效；`.p2t2c/cache/**` 是可丢弃运行状态，既不安装也不迁移。

新的收口 sidecar 是 `docs/closure/evidence/EV-*.jsonl` 下的项目拥有文件。安装和升级只能管理目录 README，绝不能管理证据实例。

受管文件 mode 现在是确定性策略：默认 `0644`，少量可执行入口显式为 `0755`。checksum 有效但 mode 错误的源会被拒绝；目标字节相同但 mode 漂移时事务化修复，rollback 恢复旧 mode。`smoke-daily` 可按 changed path 选择 focused suite 作为本地反馈，但发布与收口证据仍必须使用 `--suite all`。

安装与升级还要求 leaf 由当前用户拥有、是单链接 regular 文件且 mode 安全。Checksum 校验后冻结 source parent 与 leaf 的 identity、mode 和 digest，每次 copy 都通过相对 `O_NOFOLLOW` 读取重新核对；相对原子写之前也冻结 destination parent。第一次 target mutation 之后的任何错误或 signal 都通过同一个幂等 rollback 再退出；hardlink、source replacement 与 destination-parent replacement 都会拒绝且不修改 victim。

## 安全升级与回滚

先执行 dry-run。Apply 校验源 inventory 与 checksum、保留文件 mode，并运行已安装 checker；post-apply 验证失败时恢复旧受管字节与 lock。Rollback 只删除本次升级创建的文件并恢复所有更新的受管文件；活动 run、cache、项目配置、历史制品与证据 sidecar 都不是 rollback 目标。
