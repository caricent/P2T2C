# 0.10.1 to 0.11.0 Migration

This migration strengthens single_task acceptance merging, self-reporting, and failure triage discipline. It does not introduce business rules or modify project Truth.

## Behavior changes

- `.p2t2c/prompts/05_execute_single_task_prompt.md` adds R1/R2/R3:
  - R1 allows consecutive tasks in the same spec, same domain object, and same-source suite to merge the full Acceptance run at the chain endpoint.
  - R2 uses a project-extensible allowlist for environment failures, with at most one retry after a match.
  - R3 requires triage after failure, with fixed labels: `compile_error`, `unit_assertion`, `sandbox_environment`, `runtime_crash`.
- `docs/sot/governance/P2T2C_GOVERNANCE.md` adds `RULE-GOV-013`, limited to the self-reporting contract: each task declares `Acceptance scope:`, and any failure records a triage label plus retry count in Actual.
- `.p2t2c/templates/execution/tasks.md` adds the default `Acceptance scope: single` field, failure Actual examples, and final acceptance checks.
- `phase_rules.txt` is still generated by `check_p2t2c.sh`; `single_task` and `acceptance` automatically include `RULE-GOV-013`.

## Project-side recommendations

Downstream projects may define a feature-level closure command such as `make closure`, with the meaning of the project's non-UI, non-perf acceptance set. P2T2C does not require this command name; projects without it can keep using their own feature-level build/test/check commands.

Downstream projects may also define warm test variants such as `<test-target>-warm` to skip repeated builds after one successful build. This belongs to the project's build script, not to the upstream P2T2C workflow shell.

Project-stack R2 environment keywords and R3 triage tool paths belong in the project-owned `AGENTS.md` or equivalent AI entrypoint, not in managed `P2T2C_AGENTS.md`.
