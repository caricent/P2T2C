# 0.15.0 升级到 0.16.0 候选版

当前构建为 0.16.0-rc.1。项目接入支持时，模型为适用的简单 R1 优先选择 compact；其余沿用 standard v1。按实际支持范围验证，不以固定数量的长期效率或跨设备试点阻塞交付，不宣称未经验证的稳定性或提速比例。

## 保留与新增

保留既有 SP/design/tasks v1、archive --spec JSON、legacy 配置与证据，不自动压缩或转换。新增 compact R1 单 SP、create、按 SP 校验/归档、显式恢复以及同身份扩展。项目仍定义必要检查，核心不编排测试或推断全部语义。

## 接入步骤

1. 在选定发行根完成 source checksums 与 dry-run，处理受管文件冲突后 apply；升级不覆盖项目拥有的入口、SOT 和记录。
2. 在项目自己的治理变更中，让 AGENTS、CLAUDE、Cursor 指向统一规则；把默认整文件读取改为适用条款和依赖，保留真实项目门禁。
3. 项目包装命令必须识别稳定 SP 和真实主记录；未适配前保持 standard。证据复用、归档后清理与权限仍由项目定义。
4. 在已安装工具的新会话核对实际行为，记录缺失环境与未同步内容；文件存在不证明已经生效。

## 扩展与恢复

准备目录包含 proposal.md、design.md、tasks.md 和准备时 SP 的 source.sha256；也可用 --source-digest 传入。定向 validate 返回 source_digest。工具拒绝旧候选覆盖已变更源文件，并保留原结构化进度和检查结果。完整语义保留仍需差异审阅。

中断后重试原命令，或运行 p2t2c recover --proposal SP-... --json。事务恢复只处理绑定的工作，不借另一份 SP 的原件恢复。出现并发用户内容时保留并报告具体路径，不能强制覆盖以获得通过。

.p2t2c/documents/ 和 .p2t2c/prepared/ 是本地运行/准备区，建议加入项目自己的忽略规则；不是日常要填写或提交的证据账本。成功事务清除内容副本，保留小型机械恢复/幂等元数据。

## 回退

使用当前 0.16 提供的 upgrade/rollback 入口。替换工具前检查目标版本能力；不兼容 compact，包括 completed，或未完成事务都会拒绝。不要只修改 schema 数字或为降级自动转换记录。

已发布旧脚本无法获得这项新预检；手工复制旧运行时不能承诺兼容。布局迁移仍独立使用 docs-migrate，不能与文档写入或未恢复事务交错。
