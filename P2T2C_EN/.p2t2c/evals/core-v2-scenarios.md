# Core 0.16 Optional Outcome Observation

This reference supports maintainers during actual use. It is not a task checklist or a fixed release sample plan.

Observe whether one person and AI encounter fewer interruptions, repeated work, and corrections. Prefer naturally occurring work without manufacturing 10–20 tasks, three comparison arms, or qualification for every tool.

| Scenario | Observe |
| --- | --- |
| Clear small repair | Relevant reading, a minimal record, and sufficient checks without repeated approvals or full regression |
| Important decision or ordinary failure | Ask only for missing consequential decisions; repair ordinary failures autonomously |
| Missing necessary acceptance | Report the gap instead of confusing valid fields with actual success |
| New session or SOT maintenance | Continue useful work with applicable rules and exceptions, without repeated forms or repository-wide cleanup |

Use existing automation for changed formats, Archive, compatibility, and content protection, not on ordinary consumer tasks. Validate a consumer's actual path before claiming support. Cross-device, multiple-tool, and long-term efficiency observation are optional extensions; claim no speed ratio without evidence.

For concrete failures, identify missing information, tool support, or a rule and add only a targeted remedy. Long-term efficiency data is not yet available and does not block work whose necessary conditions are satisfied.
