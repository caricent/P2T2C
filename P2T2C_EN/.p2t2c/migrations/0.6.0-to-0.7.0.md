# 0.6.0 to 0.7.0 Migration

## Summary

This migration further reduces P2T2C root-file conflicts after installation. It avoids colliding with a user's own `README.md`, `AGENTS.md`, `Makefile`, and common metadata files.

P2T2C keeps the human and AI entry files at the project root, but gives them P2T2C-specific names:

- `P2T2C_README.md`
- `P2T2C_AGENTS.md`

Other P2T2C metadata moves under `.p2t2c/`.

## Path mapping

| Old path | New path |
|---|---|
| `README.md` | `P2T2C_README.md` |
| `AGENTS.md` | `P2T2C_AGENTS.md` |
| `CHECKSUMS.sha256` | `.p2t2c/CHECKSUMS.sha256` |
| `P2T2C_TEMPLATE_VERSION` | `.p2t2c/VERSION` |
| `P2T2C_LICENSE.md` | `.p2t2c/P2T2C_LICENSE.md` |
| `project_config.example.yaml` | `.p2t2c/templates/project_config.example.yaml` |

## Upgrade rules

- New installs no longer create root-level `README.md`, `AGENTS.md`, `Makefile`, `CHECKSUMS.sha256`, `P2T2C_TEMPLATE_VERSION`, `P2T2C_LICENSE.md`, or `project_config.example.yaml`.
- Existing projects remove old root files only when their current hash matches `.p2t2c/lock.sha256`.
- Locally modified old `README.md`, `AGENTS.md`, or `Makefile` files stop the upgrade and produce a conflict report.
- If an AI tool only auto-loads root-level `AGENTS.md`, users should manually reference `P2T2C_AGENTS.md` from their project-owned `AGENTS.md`.

## Obsolete managed files

The upgrade script may remove these old paths when their lock hash proves they were not locally modified.

```text
BEGIN_OBSOLETE_MANAGED
README.md
AGENTS.md
CHECKSUMS.sha256
P2T2C_TEMPLATE_VERSION
P2T2C_LICENSE.md
project_config.example.yaml
Makefile
END_OBSOLETE_MANAGED
```
