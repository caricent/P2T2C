# 架构决策记录

ADR 用于记录重要决策为什么成立。SoT 定义当前可执行行为。

ADR 不再是每个 R2 的固定产物。以下需要长期解释的 R2 变化通常需要 ADR：

- 架构原则或核心工作流。
- 数据真相源。
- 外部 API、协议或同步边界。
- 权限、安全或隐私边界。
- AI 职责。
- 难以逆转且需要长期解释的技术选择。

如果 ADR 被接受，必须把当前可执行规则投影到 `docs/sot/**`。当前用户指令已经明确决定完整语义时，可以记录 `gate_a: satisfied`，无需重复批准。

R1 不得通过 ADR 修改 Truth。CPK、work、机器证据和 CR 也不能替代 SoT。
