# 0.11.0 to 0.12.0 Migration

This migration replaces the per-task exception-gated process with a five-stage risk-routed workflow. It updates only the P2T2C workflow shell and does not modify project-owned Truth, ADRs, SPs, CPK instances, specs, code, tests, or historical CRs.

## New Workflow

```text
Intent Admission -> Risk Routing and Truth -> Work Batch Execution -> Verification and Repair -> Drift and Closure
```

- Adds `R0`, `R1`, and `R2` risk levels.
- Adds `docs/change_packs/` and persistent `CPK-*` contracts.
- R1/R2 continue using a compact trio under `specs/{feature}/`.
- Every completed change creates a `CR-*`.
- Gate A controls only undecided R2 semantics; Truth Drift continues to use Gate B.
- The first verification failure allows bounded autonomous repair.

## Rules Leaving the Current Workflow

- `RULE-GOV-010`: code `Implements: RULE-*` anchors.
- `RULE-GOV-011`: per-line EARS/task Rule ID tags.
- `RULE-GOV-012`: phase `Phases` fields and generated phase map.
- `RULE-GOV-013`: single-task Actual results, Acceptance scope, and fixed triage labels.

Historical artifacts remain valid and are not backfilled or rewritten.

- Historical SPs, CPKs, specs, tasks, and CRs remain valid.
