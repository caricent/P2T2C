# 0.12.0 to 0.13.0 Migration

This release adds P2T2C's native execution method layer: design refinement, risk-aware TDD, root-cause debugging, independent review, and workspace isolation. It updates only managed workflow assets and never rewrites project-owned Truth, ADRs, artifact instances, specs, code, tests, or historical CRs.

## New Install Behavior

New installations receive a `methodology` example configuration with `enforcement: required`. New R1/R2 CPK templates declare `methodology_profile: p2t2c-balanced-v1` and new execution/closure templates record method checkpoints and evidence. New CPK and closure templates declare `schema_version: 2`; v2 closures also declare `verification_policy: fresh_pass`.

## Existing Project Compatibility

Existing `.p2t2c/project_config.yaml` files are not modified. Without a `methodology` section, governance checks use advisory mode and historical artifacts remain valid. To enable required enforcement, add the configuration block from the new example and use the new CPK/spec/plan/tasks/CR templates for new work.

Required-mode method-enabled closures need fresh verification evidence, test-first RED evidence or a documented exemption, isolation/baseline evidence, and the required independent review verdict. R2 always requires independent review.

## Safe Upgrade

Run upgrade dry-run first. The upgrade creates the native skills and attribution reference only when no local managed-file conflict exists. No managed assets are obsolete in this migration.
