# Migration from 0.14.0 to 0.14.1

This patch release reduces default context and duplicate execution without changing the `p2t2c-adaptive-v2` risk, Gate, review, or repair contract. Upgrade replaces only release-managed workflow assets. It does not rewrite project configuration, Truth, ADRs, instance CPK/CR files, evidence sidecars, active run state, code, tests, or databases.

## New-install behavior

New installations include deterministic `p2t2c context`, `status`, and `evidence summary` views; three phase skills; receipt v2 with content-addressed evidence sidecars; the one-process checker and safe closed-proof cache; and coverage-aware batch verification. The project-owned configuration is now a compact identity/advisory overlay over managed `.p2t2c/defaults.yaml`. Verification command objects may declare `read_only`, `parallel_group`, and `covers`. The default profile remains `p2t2c-adaptive-v2` in advisory mode.

## Existing-project compatibility

Upgrade preserves `.p2t2c/project_config.yaml` byte for byte and keeps the effective digest and meaning of a complete legacy configuration. Existing command objects without the optional metadata keep the 0.14.0 defaults (`read_only: false`, no parallel group, no coverage). An omitted controlled section inherits managed defaults; an explicitly present but incomplete methodology, verification, or mapping override stops validation instead of silently mixing layers. Historical inline receipt v1 closures remain valid and are not converted to sidecars. Existing schema v2/v3 artifacts and open `.p2t2c/runs/**` ledgers remain valid; `.p2t2c/cache/**` is disposable runtime state and is never installed or migrated.

New closure sidecars are project-owned files under `docs/closure/evidence/EV-*.jsonl`. Install and upgrade may manage only the directory README, never evidence instances.

Managed-file modes are now deterministic: the managed mode policy defaults to `0644` and names the small executable `0755` set. A checksum-valid source with wrong modes is rejected. Identical target bytes with mode drift are repaired transactionally, and rollback restores the prior mode. `smoke-daily` may select focused suites from changed paths for local feedback, but release and closure proof still require `--suite all`.

Install and upgrade also require current-user-owned, single-link regular leaves with safe modes. After checksum validation, source parent and leaf identity, mode, and digest are frozen and rechecked through relative `O_NOFOLLOW` reads before every copy. Destination parents are frozen before relative atomic writes. Any error or signal after the first target mutation invokes the same idempotent rollback before exit; hardlinks, source replacement, and destination-parent replacement are rejected without modifying their victims.

## Safe upgrade and rollback

Run dry-run first. Apply verifies the source inventory and checksums, preserves file modes, and runs the installed checker. Post-apply validation failure restores the previous managed bytes and lock. Rollback removes only files created by this upgrade and restores all updated managed files; active runs, cache state, project configuration, historical artifacts, and evidence sidecars are not rollback targets.
